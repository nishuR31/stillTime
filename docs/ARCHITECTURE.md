# Architecture

## Shape

Stilltime is an Expo (managed-prebuild) app with two native pieces:

```
┌─ JavaScript ───────────────────────────────────────────────────┐
│  app/            screens (dial, diagnostics, testing, info)     │
│  src/domain/     pure logic, no I/O, no React                  │
│  src/state/      reducer + provider, owns the view of truth     │
│  src/native/     typed bridge and error model                  │
└───────────────────────────┬────────────────────────────────────┘
                            │ typed, awaited calls
┌───────────────────────────▼────────────────────────────────────┐
│  modules/screen-timeout     Kotlin Expo module (library)        │
│    TimeoutEngine            canWrite / putInt / read-back       │
│    StayAwakeStore           durable session state               │
│    ScreenOffProbe           ACTION_SCREEN_OFF measurement       │
│    StilltimeWidgetContract  shared constants                    │
└───────────────────────────┬────────────────────────────────────┘
                            │ SharedPreferences + broadcasts
┌───────────────────────────▼────────────────────────────────────┐
│  android-widget/           RemoteViews widget (app module)     │
│    StilltimeWidgetProvider  quick presets, Stay Awake toggle    │
└────────────────────────────────────────────────────────────────┘
```

`android/` is generated by `expo prebuild` from these sources and is
git-ignored.

## Layering rules

The dependency direction is one-way: `app/` → `src/state/` → `src/native/` →
native. `src/domain/` sits underneath and imports nothing from the others.

- **`src/domain/`** is pure. `timeouts.ts`, `dialScale.ts`, `stayAwake.ts`,
  `powerPolicy.ts` and `screenOffProbe.ts` take values and return values. This is why they are cheap to
  test exhaustively and why the awkward parts (bounds, rounding, restore
  refusals) can be reasoned about without a device.
- **`src/state/`** owns the single reducer (`stilltimeReducer.ts`) and a
  provider that sequences native calls. The reducer is pure and tested
  directly; the provider is thin glue that also owns polling and the
  `AppState` resume refresh.
- **`src/native/`** is the only place that knows the bridge exists.
  `StilltimeClient` is an interface, so `StilltimeProvider` takes a client by
  prop and tests inject `createFakeClient()`.

## The requested / applied / observed contract

This is the central idea in the codebase, and it exists because "I set it to
10 minutes" and "my phone now times out after 10 minutes" are different claims.

| Term | Meaning |
|---|---|
| **requested** | What the user asked for on the dial |
| **applied** | What Stilltime successfully wrote |
| **observed** | What `Settings.System.SCREEN_OFF_TIMEOUT` reads back *now* |

`applyTimeout()` returns `applied`; the next `getTimeoutSnapshot()` returns
`observed`. The UI shows `observed` as the authoritative value and never
presents `requested` as if it took effect. On some OEM builds a write is
silently ignored — the difference between these three numbers is how the user
finds out, and the diagnostics screen explains it.

`TimeoutEngine` performs a read-back immediately after every write and raises
`E_VERIFY_FAILED` rather than returning a value it could not confirm.

## Error model

Native failures arrive as `CodedException`s carrying one of the codes in
`StilltimeErrors.kt`. `src/native/errors.ts` maps each code to a
`StilltimeError` with a plain-language message and, where one exists, a remedy
("Open Settings to grant permission").

The codes are part of a contract shared with `STILLTIME_ERROR_CODES` in
`src/native/types.ts`. Unknown codes degrade to a generic message rather than
crashing, so a future native change cannot produce a blank screen.

## Stay Awake

`src/domain/stayAwake.ts` is a state machine, and it is where the design
decisions live:

- The session is capped at 30 minutes and cannot exceed the dial maximum.
- Starting a session records the *previous* timeout so it can be restored.
- **Restoration is refused when the live timeout no longer matches what the
  session applied.** If you changed the timeout in Android Settings mid-session,
  Stilltime does not overwrite your newer choice.
- The module never writes a timeout on its own. Reconciliation only runs when
  JavaScript asks it to.

`StayAwakeStore` persists the session in `stilltime_widget_prefs`, so the state
survives process death and can be reconciled on next launch.

## Widget communication

The widget must work when the React Native process has been killed, so it cannot
call into JavaScript. The two sides communicate through two mechanisms only:

1. **Shared state** — `stilltime_widget_prefs`, read directly by the widget.
2. **Explicit broadcasts** — `com.stilltime.app.widget.action.APPLY_TIMEOUT`,
   `...TOGGLE_STAY_AWAKE`, `...REFRESH`, handled by the provider with immutable
   `PendingIntent`s carrying a `timeout_ms` int extra.

`StilltimeWidgetContract.kt` is the authoritative implementation.
`src/native/widgetContract.ts` is the app-side mirror, and
`plugins/widgetTemplate.js` is the copy the config plugin needs — it has to be
CommonJS because Expo's config loader cannot traverse a TypeScript module
graph. `src/native/widgetContract.test.ts` asserts all three agree, so the
duplication cannot drift silently.

## Screen-off probe

`TimeoutEngine` can prove it *wrote* a value. Nothing in the public Android API
lets an app prove the device *honoured* one — a battery manager or OEM policy
can discard a write that returned `true`. `ScreenOffProbe.kt` closes that gap.

Android broadcasts `Intent.ACTION_SCREEN_OFF` to every app that registers for
it (a protected broadcast: only the system may send it, but anyone may listen,
and it needs no permission). The probe:

- registers a receiver for `ACTION_SCREEN_OFF` and `ACTION_SCREEN_ON`;
- times with `SystemClock.elapsedRealtime`, which is monotonic and includes deep
  sleep, so it stays correct across the suspend that follows the screen going
  dark — `System.currentTimeMillis` is recorded only for display;
- persists with `commit()` rather than `apply()`, because the process can be
  frozen microseconds after the broadcast;
- **restores the previous timeout inside `onReceive`**, not later. The window
  between the screen going dark and the device suspending is short and
  unpredictable, so a deferred restore may never run.

`ACTION_SCREEN_ON` is the honest failure case: Android restarts its idle timer
on any input, so a screen-on before a screen-off means the attempt is
*meaningless*, not "early". The probe reports `interrupted` and the UI refuses
to display the partial number. A probe found still `armed` on next launch is
reported as `stale` — the process died before the screen went off.

Its state lives in a separate `stilltime_probe_prefs` file. That is
deliberate: the widget has no reason to know about probes, so the three copies
of the widget contract are untouched by this feature.

The judgement — tolerance, verdict, wording — lives in
`src/domain/screenOffProbe.ts` and is pure and tested. Tolerance is
`max(2s, 15% of expected)`, because short timeouts are dominated by Android's
scheduling overhead while long ones can absorb a generous relative error.

The screen is reached by tapping the build version in the footer seven times
(`useTapSequence`), the same gesture Android uses for Developer options. The
windowing and reset behaviour is unit-tested, because an invisible gesture that
regresses fails silently.

## Reading the native module

`src/native/screenTimeout.ts` resolves the module with
`requireOptionalNativeModule` from `expo-modules-core`, **not**
`NativeModules[name]`.

This is not a style choice. A Kotlin `expo.modules.kotlin.modules.Module` is
registered by the Expo Modules installer on the JSI host object
`globalThis.expo.modules`. `NativeModules` only carries TurboModules and legacy
bridge modules, so reading it always returns `undefined` and a perfectly good
release APK reports "Native module unavailable". `Constant("...")` entries are
likewise exported as plain read-only **properties**, not behind `getConstants()`.

## Dial scale

`src/domain/dialScale.ts` interpolates *geometrically* between anchor values
rather than linearly. A linear dial would spend most of its travel on the long
end and compress 15 s – 60 s into a few degrees. The mapping is monotonic,
inverts exactly, and clamps outside the bounds.

Angles are converted through a single `wrapRadians` helper. Getting the sign of
the 12 o'clock offset wrong is easy and subtle, so `pointToPosition()`
delegates to `angleToPosition()` instead of duplicating the normalisation.

## Config plugins

Three plugins run during prebuild:

- **`withGradleReferenceProperties`** reads the machine-wide
  `gradle.properties`, validates the keys Stilltime depends on, and injects
  them into the generated `android/gradle.properties`. A missing or invalid
  reference **aborts the build** rather than silently producing different
  settings. It merges rather than replaces `modResults`, so keys contributed by
  other plugins survive.

- **`withStilltimeAndroid`** copies `android-widget/**` into
  `android/app/src/main/`, rewriting a `__STILLTIME_APP_PACKAGE__` token, and
  registers the widget provider and configuration activity in the manifest. The
  token exists because the widget needs the app's own `R` class and the
  application id is configurable.

- **`withReleaseOnlyBlockedPermissions`** writes
  `app/src/release/AndroidManifest.xml` with `tools:node="remove"` for
  `INTERNET`, `ACCESS_NETWORK_STATE` and `SYSTEM_ALERT_WINDOW`.
  `android.blockedPermissions` applies to *every* variant, and a debug APK
  stripped of `INTERNET` can never reach Metro — so the network permissions are
  blocked where they matter instead of everywhere.

All three are plain CommonJS `.js` files. This is not a style preference: Expo loads
`app.config.ts` through `@expo/require-utils`, which fails on an extensionless
TypeScript import graph. See [docs/BUILD.md](BUILD.md).

## What Stilltime refuses to do

The omissions are load-bearing, not unfinished features:

- **No root, hidden APIs, or `su`.** Every write uses the documented
  `Settings.System` path available to a normal app.
- **No accessibility service or device-admin.** Stilltime does not observe or
  control anything outside its own screen.
- **No persistent wake lock or foreground service.** Stay Awake raises the
  screen timeout for a bounded window instead of holding the CPU awake, which
  is also why it can restore cleanly.
- **No background retries.** A failed write is reported and stops. There is no
  work queue that retries behind the user's back.
- **No network.** No HTTP client exists in the codebase.

See [PRIVACY.md](PRIVACY.md) for the resulting permission set.
